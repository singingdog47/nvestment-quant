# Action First: 軽量売買判断基盤（2026-11-06）

## 責務を3つに分離する
1. **Fast path（新設）**：このワークフローはstdlibのみでCME日経円建て先物（大阪先物ではない）、米国株指数、VIXの**取得時刻付き**急落を検知。市場のNEUTRALラベルより**独立して**CRITICAL / DEFENSIVE / CAUTION / NORMAL / UNVERIFIEDを判定する。
2. **Decision path（ChatGPT条件監視）**：最新の**非公開**楽天証券保有・注文情報を照合してから、売買・取消・維持の優先順位、保有数量、成行/指値、執行期限を明示する。注文を実行したふりはしない。
3. **Research path（既存）**：全市場スクリーナー、会社情報、レジーム、仮想売買等は研究・日次/週次レビュー用に残す。緊急判断の**必須前提にしない**。

## 設計上の制約
- 最新出力: \`data/action_first/latest.json\`、\`latest.md\`。公開リポジトリには**保有資産、取得価額、注文、個人情報を保存しない**。
- 短いスケジュール・依存パッケージなし。Yahoo Chartの非公式価格は取得失敗・時刻超過を**UNVERIFIED**として扱う。信頼できる現在値やJPX公式先物での二重確認は別系統の判断側で行う。
- Github Actions cronとChatGPT条件監視は実行・通知時刻を保証しない。超短期の損失制限に使う場合は証券会社側の逆指値等が必要。
- CRITICALでも**自動売買しない**。マーケットレベルの勧告から個別売買を断定せず、非公開PF、最新注文、出来高、企業情報と照合する。
- VIX20以上でもマーケットレジームを無理にRISK_OFFに書き換えない。売買優先の**独立警報**を立てる。
- 既存パイプライン・仮想台帳を変更しないため、退避とロールバックが容易。

## 合格条件（未検証）
- 直近のような日経円建て先物-5%超やS&P500-4%超をNEUTRALに潰さずCRITICALと判定
- 欠損・古い価格を「警報なし」にしない
- 原則、CRITICALから最初の人間向け通知は「重要変化が確認できた場合のみ」
- 急変後の寄り付き時点で注文維持/取消・売却/維持を個別に判断し、確認できた状態と未確認を区別
- 過去の急落・反発で検知率、誤警報、意思決定の効果を後方検証。GitHubの成功表示だけで合格としない
